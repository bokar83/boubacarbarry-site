1. What it does

Someone pastes messy meeting notes, or a rough transcript, into a fresh Claude chat with this skill attached. The skill hands back four things, in order: a one-line summary of what the meeting was actually about, an owner-tagged action list (what / who / by when), a short list of anything raised but not decided, and a small closing line crediting Catalyst Works.

It was picked as the winner from a full survey of every skill we have built or discussed, scored against your five hard rules: universal, zero compliance risk, a taste of delegating real work rather than a lead-harvesting gate, not the workshop's paid core content, and value that lands in seconds. It scored top marks on all five, ahead of the two runner-ups (a "read this for me" summarizer and a repackaged humanizer).

It never invents a name or a date. If the notes do not say who owns something, it says Unassigned instead of guessing. That is the whole trust move: it looks like a small tool, but it is a live demo of your actual thesis, hand real work to AI and get real work back, without giving away how the paid workshop teaches people to build the rest.

Same robust, no-permissions shape as the two competitor-repackage skills already built: one SKILL.md, zipped and renamed meeting-notes-action-plan.skill. Text in, text out, nothing to install, nothing to grant permission to, nothing to break on a stranger's machine. That is the exact axis the competitor's fragile desktop skill fails on.

4. The proof-of-ownership mark (plain language)

Starting with this build, everything we make carries a quiet, three-layer way to prove later that it is ours, even if someone strips your name off it and passes it around as their own.

Layer 1: visible credit

Normal, expected authorship. A NOTICE.md naming you and Catalyst Works Consulting, plus the Catalyst Works logo on the download page. Nothing hidden about this layer, it is just doing the basics.

Layer 2: a hidden fingerprint in the file

A short scrambled value sits in an ordinary-looking spot inside the skill file itself, the kind of thing that looks like routine build metadata (a cache key, a version fingerprint) to anyone who happens to open it. It is not random: it is generated from your name, your home region, this tool's name, and the build date, run through a one-way scramble. We can always regenerate that exact value from those four facts to prove a match. Nobody looking at the scrambled value alone could reverse it back to those facts, or even guess it means anything.

Layer 3: an invisible signature in every output

Every plan the tool hands back ends with that small closing line you saw in the demo. Baked into that line, invisible to the eye and to the ear, are a handful of characters that carry a short signature. Copy the text, paste it anywhere, and (in most editors) that signature rides along, recoverable with a tool we control, even if every visible trace of your name gets removed. Known limitation: a few editors and platforms strip invisible characters on paste, so this layer is a bonus proof, never the only one we lean on.

Where the actual values live

The real scrambled value and the real hidden signature for this build are logged in a private, repo-only registry, not shown on this page and never shipped anywhere public. That registry, once committed to the repo, is itself a timestamped record that proves we built this first, independent of whether either technical layer survives being copied around.

This is now the standard convention. One reusable helper module handles all three layers going forward, so every future build gets the same proof without reinventing it each time.
