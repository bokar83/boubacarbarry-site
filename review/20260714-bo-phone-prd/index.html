B1b. Legal disclosure for recording GO · bundled with B1

Researched fresh (2026-07-14): Utah is a one-party consent state — you, as a party to your own calls, can legally record without telling the other side under Utah law alone.

But calls cross state lines. Federal law sets a one-party floor and does NOT override stricter state law — California, Washington, Nevada and others require all-party consent. Since Bo can call or receive calls from anyone anywhere, the safe move (and exactly what you already said — "as all businesses do") is to disclose on every call, no matter where the other person is.

The fix: one spoken line near the start of any recorded call — something like "This call may be recorded for quality and training purposes." Fires only when recording is actually on, so it doesn't clutter test calls.

B4. Google Fi <-> Bo connection THE BLOCKER · next step below

Your ask, current priority: "figure out how to get my Google Fi line to connect with Bo for automatic pick up and responding."

Fresh, deep research (2026-07-14) — definitive answer:

  • The standard GSM code (*61*<number>#) for no-answer forwarding technically rides on Fi's underlying T-Mobile network, but it's unofficial on Fi and you already tested it live and it failed — that real result overrides any generic "might work" guidance. Treat this path as closed.
  • Fi's own app/web settings re-confirmed: only 3 modes exist — Don't forward / Always forward / Ring all numbers. No conditional (no-answer) option exists in the product, period.
  • No reliable Android app was found that fixes this for a Fi line specifically — Fi's own hybrid network (native cellular vs its own VoIP/Wi-Fi-calling layer) is likely WHY the star code failed for you in the first place, and an app sitting on top of that same inconsistency isn't a real fix.
  • Telnyx's own dial API DOES support exactly the mechanism needed for the alternative approach: a timeout (5-600s) that fires a hangup webhook when unanswered — confirmed real, not a guess.
