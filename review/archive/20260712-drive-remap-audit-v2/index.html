D. The reusable methodology (sellable as a system, not a one-off patch)

Written so anyone facing the same mess (a person or an AI) can run it on any file store: Drive, Dropbox, a file server.

The method in 6 steps

  1. Freeze a reference. Never reorganize in place. The pre-reorg tree becomes an immutable reference (here: _ORIGINAL_TREE). Declare which tree is canonical going forward and write down the reference tree's endgame (human-deleted after verification, never auto).
  2. Inventory + classify at the FOLDER level. Enumerate all folders cheaply first (names + parents only; files can wait). Classify every source folder COHERENT (single subject: moves whole) vs CATCH-ALL (mechanical test: dump-name list match, or zero subfolders with 20+ files). Bias to coherent: the wrong-whole-move costs one messy folder; the wrong split costs the whole reorg.
  3. Define topic magnets + a retrieval-ordered routing tree. One canonical destination per ask ("everything about X"), with precedence = how the owner asks: entity → life-domain → work → learning → lifecycle → media → inbox. Then sweep for strays TWICE: by folder NAME (synonyms + aliases) and by CONTENT PATTERN (filename tokens like W2/1099/IRS), requiring a second signal on pattern matches to kill false positives.
  4. Place in Phase A, dedup in Phase B. Never together. Phase A only places (move within canonical tree; copy from frozen reference; copy-out from Vault units). Phase B hashes inside each now-correct destination, reconciles quarantine, and produces a human deletion manifest. Mixing the phases is what created the shadow-tree mess being repaired.
  5. Dual-home the un-dissolvable. Big historical transfer dumps go WHOLE into a Vault top-level (immutable, browsable in original form, admission checklist logged), and only their magnet-relevant contents are copied out. This resolves the false choice between "dissolve grandma's boxes" and "lose findability".
  6. Verify per unit, ledger per source. Every move/copy verified by re-fetch (recursive count + hash-set subset). Every source folder gets exactly one recorded disposition in a coverage ledger; an unmapped source is a blocker. Machine-verifiable done-conditions per program (name-search returns only canonical paths; counts reconcile).

Standing guardrails (unchanged from v1, restated as method rules)

  • Every mutation by immutable ID; names only for the initial lookup. Verify-after-state, stop-on-anomaly, batch receipts.
  • Media units are atomic. Sensitive folders are opaque IDs (no content reads, no names in outputs).
  • Dev-junk exclusion (node_modules, .git, dist, build, __pycache__, venv): never migrated, never counted.
  • Two-phase landing inside a magnet: land whole, organize inside afterward.
  • No deletes by agents, ever: one quarantine + a human deletion manifest.
  • Operational: enumerate folders-first; file queries scoped + streamed with a memory cap; never unbounded inside a production container (this audit's two container restarts are the documented counterexample).
