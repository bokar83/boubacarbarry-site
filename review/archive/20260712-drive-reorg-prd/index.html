Drive Reorg (bokar83 Google Drive Remediation + Librarian Rule System) — Build Contract

Constraint-First Build Spec · 2026-07-12 · drive-plan lane · Normative technical spec: docs/audits/drive-remap-audit-2026-07-12-v3.html (final, externally reviewed). This PRD is the decision instrument on top of it. Canonical/working copy: docs/plans/2026-07-12-drive-reorg-prd.md.
1. One-Line Verdict: GO — Boubacar has personally driven three plan versions, two external AI reviews, and five decision rounds in a single day; the demand is his own, the plan survived every gate, and the cost of NOT fixing it is measured (202,754 files reachable only in a tree scheduled for eventual retirement).
2. The Single Problem

A prior agent "reorganized" Boubacar's entire personal Google Drive by COPYING instead of moving, classifying item-by-item instead of folder-by-folder, and silently skipping 10 of 38 top-level folders — leaving ~1.22 TB of unreconciled duplication, tax records scattered across 5+ locations, two critical Guinea folders absent from the live tree, and no filing logic that a human OR an AI can predict. Boubacar cannot trust that anything is where it should be, or that anything is not lost.

3. The Non-Negotiables
  • READ-ONLY until Boubacar's explicit go-ahead AND a green Execution Readiness Gate (finite 5-item checklist; plan Section E). Plan approval alone does not start execution.
  • _ORIGINAL_TREE is an untouchable frozen reference until the Boubacar-only endgame; frozen-ness is actively VERIFIED (the sweep caught live writers violating it).
  • Agents NEVER delete anything. 90 The Holding Pen + a human deletion manifest is the only deletion path.
  • Sensitive folders (private family folder, .pa we instances, GN Closure Files, hidden media vault) are opaque IDs: never read, listed, or named in any output.
  • Every mutation by immutable file ID with verify-after-state and a written receipt; stop-on-anomaly halts the batch.
  • Canonical tax name is Impots; year subfolders are created as encountered in documents — no assumed start or end year (records may predate 2005).
  • Bulk enumeration is chunked + resumable + memory-capped, never one giant fetch inside the production container (two documented incidents this session define the failure class).
4. What We Will NOT Build (8 vetoes)
1. No wholesale top-level redesign. The numbered-zone shape is right (verdict upheld across v2, v3, and both external reviews); redesign would cost thousands of moves for zero retrieval gain. Only the four surgical revisions ship.
2. No dedup during placement (Phase A). Dedup logic in the placement pass is exactly what created the shadow-tree mess being repaired; Phase B is a separate, later sweep.
3. No silent folder skips. Every one of the 38 original sources has a line in the coverage manifest — including LEAVE and EMPTY rows. An unmapped source is a blocker, not a silence.
4. No agent deletion, ever. Not trash, not hard-delete, not "obviously safe" duplicates. Boubacar is the only deleter.
5. No naming-based "hiding" for private content. A dot-prefix hides nothing in Drive's GUI; privacy comes from ACL restriction on the folder ID. Names are labels.
6. No unverified shortcuts. Drive shortcuts do not grant access; every shortcut dual-home passes an ACL-equivalence preflight and FAILS CLOSED to a physical copy.
7. No exhaustive per-file review. At the measured 544,630-file scale, universal item-level inspection would explode API limits and container memory; review is universal but hierarchical (light inventory-level for coherent folders, per-item only for catch-all/flagged/receiver folders).
8. No new tooling beyond the readiness-gate list. Receipt writer, ledger file, preflight greps, ACL check, resolver — that finite list, nothing speculative.

Boubacar, a fractional operator with 15+ years of records (tax filings back past 2005, immigration dossiers, a Guinea family archive, a dozen ventures) who needs to find any document in seconds during a client call, a tax deadline, or a legal matter — and needs to trust that nothing was silently lost.

Explicitly in scope as the second archetype: any future AI session (librarian skill, Claude/Codex lanes) that must file a new drop or retrieve a document mechanically, with no human judgment in the room — the filing logic must be restatable as rules or it is wrong.

9. Tech Boundaries
  • Yes: Google Drive API v3 via the canonical DriveOps helper (by-ID, verify-after-state, identity-asserted), run from the production container; chunked resumable enumeration with checkpoints; flat JSON ledger + receipt files; Drive-native shortcuts and ACLs.
  • No: rclone root-remap operations (banned since the 2026-06-03 incident); path/name-addressed mutations; name+size dedup (md5Checksum only; Google-native null-md5 files go to quarantine review, never auto-judged); OCR/content-classification in the mechanical routing tree; any new dependency beyond stdlib + the existing Google client.

12. The Failure Modes (top 3)
  1. Path-based automation breaks when PGA / Inner Circle / aiHQ move. Mitigation: HARD blocking preflight gate with explicit grep targets across repo + VPS configs + n8n DB; ID hits safe, path hits = stop and repoint; aiHQ resolved by the repoint-first tradeoff rule.
  2. Execution drift from the plan (Codex's named top risk). Mitigation: per-move receipts (no receipt = it did not happen), stop-on-anomaly, the Execution Readiness Gate before mutation one, and Phase A/B separation enforced structurally.
  3. Silent copy loss repeats (the 31→28 class). Mitigation: per-unit recursive count + md5-set verification on every copy, coverage-manifest closure over all 202,754 gap files (every one ends explained: excluded-by-class / copied / rescued / quarantined).

Accepted residuals (recorded): name-opaque media files as media (no OCR); Kachet spelling unverified pending Boubacar.

20. Voice & Tone Spec

For user-facing strings (librarian-skill messages, receipts summaries, triage notes): plain operator English, terse, factual, zero hype; state what happened and what is needed, never what "should probably" happen. Bilingual-aware matching (French terms recognized) with English labels except the canonical Impots. Banned: internal codenames in anything that could leave the system (per the standing copy rules), em-dashes in Boubacar-voiced text, invented numbers, cutesy anthropomorphizing ("I tidied up for you!"). Sensitive folders are never named in any message — ID or the phrase "a private folder" only.

21. The Anti-Pattern Watch
  1. The Vault (or the hidden vault) becoming a second Attic — a soft landing spot for anything nobody wants to route. Guard: four-condition admission checklist, agent-proposes/Boubacar-admits, every admission logged.
  2. Plan approval treated as execution start. Guard: the Execution Readiness Gate is a separate, finite, machine-verifiable barrier; Codex's execution-drift warning is recorded in the plan and here.
  3. "One more quick move" scope creep during execution — an operator or agent slipping un-contracted moves into a batch because the tooling is warm. Guard: every mutation needs a receipt tracing to a contract row; anything else halts the batch. New scope = new PRD.
