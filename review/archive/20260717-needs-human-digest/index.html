RECURRING · 4x, ROOT CAUSE FOUND VPS deploy blocked, 12 days running▸

Four halts, same server (srv1040886), two different error signatures: "cannot change to '/root/agentsHQ': No such file or directory" (July 5, July 7 — ids #1018/#1047) and "Unable to create '/app/.git/index.lock': Read-only file system" (July 16, July 17 today — ids #1406/#1474).

This class is already on the auto-fix allowlist (vps-deploy-halt has had a real auto-fixer since it was added — it runs git checkout main + pull --ff-only and verifies HEAD matches origin before calling it fixed). Reading that fixer's code found why it keeps failing anyway: it resolves its own repo path via repo_paths.repo_root(), which always points at wherever the fixer's own process is running — /app inside the container. The second signature is structural, not transient: if /app is mounted read-only inside the container (by design, so the running code can't self-modify), the fixer's own git checkout can never succeed there — every future occurrence of this specific signature will keep failing the same way. The first signature (directory briefly missing) looks more like a one-off host-side hiccup, not the same bug.

Recommendation: this is a scope decision, not a code fix I can safely make solo — either (a) the fixer should stop attempting this class of fix entirely and just log-and-notify (since it can't win against a read-only mount), or (b) the mount policy needs a narrow, explicit exception for this one write path. Both are infra/deploy-path changes gated Tier-C in this repo (human review required regardless of confidence score) — recommend you pick the direction, then it's a same-day fix once decided.
Your call — no single recommendation, pick a direction
