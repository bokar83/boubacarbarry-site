Second Brain Full Access -- Plan of Action

PRD review · ms02-init lane · 2026-09-17

TL;DR

This is not a green-field build. A Postgres-backed second-brain pipeline already exists and already indexes memory/, your governance docs, decisions, PRDs, and 4 named Notion databases -- every lane and VPS crew already queries it via one CLI (ask.sh). The gap is real but narrow: it cannot see Drive, NotebookLM, or Notion outside those 4 databases.

Phased plan, cheapest first:

  • Phase 1 (build authorized by this PRD, buildable this week): wire full-workspace Notion search into ask.sh -- reuses a tool already connected, near-zero build cost.
  • Phase 2 (planning only): NotebookLM ingestion via the VPS nlm CLI -- needs a short capability spike first, its own PRD.
  • Phase 3 (planning only, blocked): Drive ingestion -- the real build. Blocked on YOU answering the open question below before it can even be scoped.

Both Karpathy (10-principle code audit) and Council (5-voice adversarial review) ran on this plan before it reached you -- see the section below for what they changed. Verdict: SHIP Phase 1, with two fixes already applied.

The one thing only you can answer: does "every single thing in Drive" include the immutable _ORIGINAL_TREE folder and the opaque "Pa We" folder for search/read purposes, or do those stay excluded the way they're already excluded from mutation? See the Open Question section.

1. The phased plan

Your instruction was "every single thing in Drive, NotebookLM, and Notion needs to be accessible, and other lanes and VPS crews use it too." The system already does most of that for the file/document side of this (memory files, governance docs, decisions, PRDs) and for 4 core Notion databases. The gap is specifically: full Notion workspace search, NotebookLM, and Google Drive.

2. Phase 1 -- what actually builds this week

Add a live Notion-search leg to the existing ask.sh query tool (the one every lane already uses). It calls the Notion search tool that's already connected to this session, or the Notion API directly from VPS crew containers using the same credential the nightly Notion sync already uses. No new database, no new cron job -- it's a live lookup at query time, merged into the same result list agents already read, clearly labeled so a live Notion hit is never confused with an indexed one.

Ship bar: works correctly on 2 real test questions whose answers live only in an un-synced Notion page; degrades loudly (never silently) if Notion times out or rate-limits; deployable within days, not weeks.

3. Phase 2 & Phase 3 -- planned, not authorized to build yet

NotebookLM (Phase 2): the only working path is the VPS nlm CLI (your laptop's connection to NotebookLM is blocked by the TLS interception on this machine). Before this can be scoped into its own build plan, someone needs to spend a short session confirming exactly what nlm can export -- source lists, generated notes, Q&A transcripts. That spike is not done yet.

Google Drive (Phase 3): the real build. Larger, less structured corpus, and it runs directly into two of your own standing rules: the immutable "original tree" folder that's copy-only/never-move, and the "Pa We" folder that's permanently off-limits. Both rules were written about moving or editing files -- neither says anything about whether those folders should be searchable. This plan does not decide that for you (see the next section). There's also a real credential decision to make: a dedicated service account vs. reusing your own Google login, which have different tradeoffs for running unattended on the VPS.

Each of these gets its own build plan and its own Karpathy + Council review before any code is written -- this PRD's go-ahead only covers Phase 1.

4. The one question only you can answer

Does "every single thing in Drive" include the immutable _ORIGINAL_TREE folder and the opaque "Pa We" folder for search/indexing purposes?

Both are currently hands-off by standing rule -- _ORIGINAL_TREE is copy-only, never moved or edited; "Pa We" is permanently opaque, never opened or reorganized. Neither rule was written with search in mind. Your instruction ("every single thing... you use it") could reasonably mean those get indexed too, or it could mean the existing hands-off treatment should hold even for search. This plan will not guess -- Phase 3 (Drive) does not start until you say which. Also worth naming while we're at it: are there any other Drive folders (client-sensitive, personal/family, legal) you want excluded before a crawler ever touches them?

5. Karpathy + Council findings

Karpathy: SHIP Audited against all 10 principles. One WARN: the plan document scoped all three phases in one place, which could read as if Phase 2/3 were already authorized to build -- fixed by adding an explicit "planning only" banner. Everything else passed clean: the plan was researched before written, Phase 1 is genuinely the minimum build, no scope crept past what was asked, and a real done-condition was stated before any code exists.

Council: CHANGE, then ship Five independent reviewers pressure-tested the plan. Two real gaps found and fixed before this page was published:

  • The live Notion call could, under load, degrade the whole query tool for every lane if Notion is slow or rate-limited. Fixed: that leg now has to fail loudly and independently, never silently and never blocking the rest of the tool.
  • The Drive open-question above was at risk of living only in this document and quietly going stale, the way an earlier Drive plan did in September. Fixed: it now has a dated task-board row with your name on it.

One tension the reviewers surfaced rather than papered over: should this plan prove Drive/Notion coverage is actually the bottleneck before building more, or should it move fast and generalize the Phase 1 pattern to future sources? The resolution: ship the cheap win now, and let real usage answer that question before deciding what Phase 2/3 timing should be.

6. What this plan will NOT build
  • No new database -- everything extends the Postgres index every lane already queries.
  • No write/edit capability into Drive, Notion, or NotebookLM from this pipeline -- read/search only, ever.
  • No blanket Drive crawl before the exclusion question above is answered.
  • No productized "connect anyone's Drive" tool -- this is your workspace, wired for your own lanes and crews.
  • No real-time push/webhook sync in v1 -- everything runs on a schedule or at query time, matching how the Notion sync already works.
