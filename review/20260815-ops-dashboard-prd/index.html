04

Your three questions, made into honest numbers

You named the bar yourself: "how much work is being done, how effective we are that day compared to the previous days, how you are doing on usage." Here is exactly how each becomes a number, and the one trap we refuse.

QuestionMetricSourceComparison
How much work today?Tasks completed + branches merged + LLM calls executed, shown as three separate countslane_tasks, gate_log.jsonl, llm_callsEach vs its own trailing 7-day median, as a signed % chip
How effective vs previous days?The same three counts plus crew success rate, each with a 7-day sparkline and delta+ task_outcomes.successMedian, not mean, so one monster day (8/10 was 2x normal) does not poison the baseline
How is usage doing?API spend today (exact, from llm_calls) and Claude Code plan % (labeled estimate, from the digest, with its file age shown)llm_calls, digest fileSpend vs daily cap; plan % vs week
The trap we refuse: a composite "effectiveness score." Blending tasks, merges, calls and cost into one invented index would look impressive and mean nothing, and the first time it moved for a reason you could not trace, you would stop trusting the board. The whole board dies by that one tile. You get real counts with real deltas, each traceable to a query you could run yourself. This was a deliberate Council + Karpathy call, held under pressure, and it is the difference between a dashboard and a demo.
05

Design system and information architecture

The organizing principle: rows are questions, not components

Today's tiles are grouped by which subsystem feeds them. Nobody thinks in subsystems at 7am. The board reorders into five rows, each one a question you actually ask, in the order you ask them, hero strip on top:

RowQuestionTiles
0 · PulseHow are we doing right now?Work today, vs 7 days, spend today, plan usage (the hero strip)
1 · Needs meIs anything stuck on me?Gate held-by-tier "needs a tap", approvals, priority queue, inbound
2 · BrokenIs anything on fire?Errors, cron liveness, provider health, heartbeats (with the "a pulse is not proof of work" caveat honored)
3 · MoneyWhat is it costing?Spend + pacing, cost by crew, cost per completed task
4 · MovingIs the work moving?SYS backlog by priority, absorb, content, leads, live claims
5 · Roster + BrainWho is on the field, and is the memory sharp?Agent roster by function group (finally reading the manifest), second-brain corpus health

The truth contract, every tile, no exceptions

  • Source + age on the tile. Every tile carries its table name and an "as of" timestamp in the footer, small but present.
  • Three failure states, never collapsed: no signal found (a real zero), source unreadable (query failed, shown in amber), and NOT WIRED (never connected, shown as a labeled dashed box, never a fake zero). Adopted verbatim from your data-home doctrine. The monitor showing "0 done this week" with no hint the feed was stale is the exact lie this kills.
  • Read-only. Every new endpoint is a GET. No writes ride along with this build.
  • Stale sources say so. The plan-usage tile reads a laptop-written file; it renders that file's date next to the number, always.

Visual system (dataviz skill applied, validator run)

Dark-first, matched to Atlas's live brand: near-black navy surfaces, serif display headings, the orange as the single accent. The categorical palette was machine-validated against Atlas's own surface with the dataviz skill's six-check validator, all checks passing (lightness band, chroma floor, colorblind separation, normal-vision floor, contrast):

#3987e5  #d95926  #199e70  #c98500  #d55181

  • Status colors (green/amber/red) are reserved for state, never used as series colors. Series hues are assigned in fixed order, never cycled.
  • Sparklines are single-series 2px lines, one axis, no dual-axis charts anywhere, direct labels over legends where 4 series or fewer.
  • Numbers count up on load (the monitor's best trick, ported), deltas are signed chips, refresh no faster than 30s with a visible "updated Xs ago".
