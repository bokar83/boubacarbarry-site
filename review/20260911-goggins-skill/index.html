The Goggins skill

A free accountability agent for people who keep starting new things · 2026-09-11

TL;DR

I built a skill that tells me the truth about my own work, and I am giving it away. It reads the commitments I already keep, asks five blunt questions, and refuses to let the conversation end without a next action and a date on it.

Free. Copy the file from this page or download it, drop it into your skills folder, and type /goggins. It is one markdown file and it runs on its own.

What it does

Every assistant I have used is agreeable. I ask for a plan, I get a plan. I ask for a better plan, I get a better plan. It will help me plan forever, because planning is something it can always do well and finishing is something only I can do.

This one has the opposite instinct. Its job is to end the conversation, not extend it.

It asks the same five questions every time, one at a time, and it wants short answers:

  1. What did you finish since the last time we talked?
  2. What is the committed thing that is still open?
  3. What is blocking it. One sentence.
  4. From where you are standing right now, what is the fastest path to the outcome you said you wanted?
  5. Is this new idea that path, or is it a way to avoid the open thing?

Question five is the one that earns the whole thing. The other four I can ask myself on a good day. Five is the one I will not ask myself, because I already know I am not going to like the answer.

Then it makes me name one action and put a date on it. Not another plan. One action, concrete enough that a stranger could tell whether it happened.

Who it is for

People who make things and keep starting new ones. If you have ever opened a fresh project folder while an old promise sat there untouched, this was built for you. It was built for me first.

Laziness has nothing to do with it. Starting feels like progress and finishing feels like risk, and a helpful assistant will happily keep handing you new things to start.

Get the file

Here it is. Copy it or download it, both give you the same file.

Install it
  1. Make a folder called goggins inside a folder called skills. In a single project that is skills/goggins/. To have it everywhere, use ~/.claude/skills/goggins/ instead.
  2. Save the file above inside it as SKILL.md. Keep both names exactly as they are.
  3. Start a new session and type /goggins.

A skill is a plain markdown file your agent reads and follows. There is no code to run and no key to paste. If your setup does not turn skills into slash commands, it still works: say "run the goggins skill", or paste the file into the chat and tell it to follow it.

It writes what you say to a text file you own, goggins-log.md, and reads nothing else. The repeat blocker is the finding. Say the same thing is blocking you three weeks running and it will be on paper instead of in your head.

What it will not do

The failure mode of a blunt tool is that blunt turns into demoralizing, and a demoralizing tool is one you stop opening. Then it is worth nothing. So the limits are as much of the design as the questions are.

  • It never blocks you. It names the open thing, asks, writes it down, then gets out of the way. You override it every time you want to. I tried the version that locks the work behind a rule. It ran at zero for weeks and cost me the building it was supposed to protect.
  • It never moralizes. It names the avoidance and asks a question. It does not tell you what kind of person avoids things.
  • One pushback on a soft answer, and only one. Two is nagging, and nagging is how a tool like this gets closed and never opened again.
  • A dead miss stays dead. If something is late past the point where acting still helps anyone, it stays closed. There is no value in handing you a list of things you can no longer fix.
  • It never kills an idea silently. Anything it deflects gets parked with a return date and the condition that brings it back.

Why it is called Goggins

A friend and I landed on the same idea from opposite directions in a call. A blunt accountability agent. It does not brainstorm. It asks what you finished and whether the shiny new thing is the fastest path or a way to avoid the promise you already made.

We both said Goggins in that meeting, because it was the fastest way to say what register we meant. Direct, unsentimental, no coddling. The name stuck and I kept it.

I have a standing rule that the things I build get named for the work they do. This one is the exception and I made it on purpose. It was built for somebody, the name is how he and I understood each other in the first place, and it tells you in one word what the thing sounds like before you read a single line of it.

Take it, change it, pass it on. If you build a better version, I want to see it.
