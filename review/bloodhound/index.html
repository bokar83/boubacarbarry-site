How this works

Every decision on this page is a row in a real database, not a note in a browser. That is what lets the next search cycle read your history before it proposes anything, and it is why a skip reason is required rather than optional.

The contract the search cycle runs against, if you ever need to hand it to someone:

Before proposing any role, a cycle must query public.bloodhound_decisions for a matching company + title with decision = 'skipped' and must NOT re-propose it. A row with parse_ok = false is UNKNOWN, not "not skipped" -- surface it, never silently re-propose.

And the query itself:

select company, title, decision, reason_tag, reason, decided_at, outcome, parse_ok from public.bloodhound_decisions where decision is not null or parse_ok = false order by decided_at desc nulls last;

If a save ever fails you will see it in red, on the role itself, and it will not clear on its own. A save that looks like it worked and did not is the one failure this page is built to make impossible.
