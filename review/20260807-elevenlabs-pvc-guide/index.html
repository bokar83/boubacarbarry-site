Quick Answer
TL;DR
30 minutes is the floor. Budget 60–75 minutes of studio time to walk away with it.

ElevenLabs' own documentation sets 30 minutes as the minimum for a Professional Voice Clone and recommends 1–3 hours for the strongest result. Part 2 of this page (Section C, below) will design a ~44-minute raw script — that number is a zero-retake read-through estimate, not a studio-time estimate. Budget 60–75 minutes of actual recording time to land 40–45 minutes of clean, usable audio once retakes, room-tone checks, and breaks are factored in. Everything on this page below is verified against ElevenLabs' own current documentation plus cross-referenced community practice, cited inline.

Why this project matters right now

Boubacar's phone assistant already runs on an ElevenLabs voice clone tied to his own voice. ElevenLabs' own recommended first lever for improving that clone's quality is exactly this: feed it more, more varied, source audio before touching anything else. This page is the practical guide for doing that recording session well.

A. Step-by-Step: Creating the PVC

The dashboard flow, verified against ElevenLabs' own documentation and current tutorials. If the ElevenLabs UI has moved a button by the time this runs, the sequence of steps below will still hold.

  1. Confirm the account is on the Creator plan or higher — Professional Voice Cloning is not available on Free or Starter.
  2. Log into ElevenLabs, open Voices in the left sidebar, then click Create Voice (or “Add a new voice”).
  3. From the popup menu, choose Professional Voice Clone — not Instant Voice Cloning. They are different products with different quality ceilings; only PVC accepts 30+ minutes of source audio and produces the higher-fidelity result.
  4. Name the voice and set the language.
  5. Click Upload samples and add the recorded files (or use “Record yourself” to record directly in-browser). Confirm the single-speaker setting.
  6. Review the on-screen sample-length feedback. ElevenLabs shows a running total as files are added — watch for it to clear the 30-minute floor.
  7. Optional but recommended: run the built-in audio processing/cleanup tools on the samples before submitting.
  8. If any file was flagged for multiple speakers, ElevenLabs runs a speaker-separation pass — confirm which segment is the correct speaker before continuing.
  9. Record the verification clip when prompted, using the same mic and room as the training samples, in a similar tone and delivery. This step exists so ElevenLabs can confirm the voice being cloned is really the account holder's.
  10. Submit for training. ElevenLabs sends an email when fine-tuning completes (typically same-day; see the Verified Requirements table above for the range and the one conflicting third-party estimate).
  11. Once training finishes, find the finished clone under My Voices → Personal and click Use to wire it into a project or, for Bo, note the resulting voice_id for the swap into the phone-assistant config (see Open Questions below for what is and isn't verified about that swap).

B. Recording Setup

Merged from ElevenLabs' own published guidance (blog + docs) and cross-referenced community practice from people who have actually built a PVC. Where the two disagree, that is called out rather than picked silently.

Step 0 — room tone first

Before recording a single word of the actual script, record 15–30 seconds of pure silence in the room, in the exact seat and mic position that will be used for everything else. Listen back on headphones. This is the fastest way to catch HVAC hum, a fridge compressor, traffic noise, or mic self-noise before an hour of good material gets recorded on top of it. If the room tone isn't clean, fix the room (HVAC off, close a window, move rooms) before continuing, not after.

Room
  • Quiet, ideally acoustically treated (soft furnishings, curtains, a closet full of clothes all work as informal treatment). No HVAC, pets, or traffic noise running during a take.
  • Same room, same seat, same mic position for the whole session — consistency matters more than any single piece of gear.
Microphone
  • A cardioid condenser or broadcast dynamic mic is the official recommendation. An XLR mic into a dedicated audio interface is the strongest path if that gear is on hand; a decent USB condenser is a fine substitute.
  • Distance: roughly two fists from the mic, held constant across the whole session.
Format and levels
  • WAV, 44.1kHz or 48kHz, 16-bit minimum, is the safest target. MP3 is accepted if it's uncompressed-sounding and at least 192kbps — avoid heavy compression either way.
  • Flat EQ going in, no compression on the recording chain. Target roughly −23dB to −18dB RMS with true peak around −3dB; normalize afterward to about −3dBFS rather than compressing to get there.
Content and delivery
  • Single speaker throughout, spoken (not sung), natural pacing rather than a flat, over-rehearsed read.
  • Insert short silences between segments — about 1–1.5 seconds between paragraphs, a bit less between sentences — so the model learns natural pause behavior instead of a run-on delivery.
  • Vary pace, pitch, and energy across the session rather than reading everything in one register (Section C, once it ships, will label each segment with a specific pace/pitch target for exactly this reason).
  • Avoid vocal fry, throat-clearing, and filler words unless intentionally wanted in the output; clean retakes out rather than leaving stumbles in the final files.

If recording spans more than one sitting

ElevenLabs' own published guidance is explicit on this: keep mic placement, gain, and location identical across sessions, and record within the same 24–48 hour window to avoid audible vocal drift between sessions. Voice naturally shifts sitting to sitting (energy, hydration, time of day) enough that a clone trained on drifted samples can sound subtly inconsistent. If the full session can't happen in one sitting, same room / same mic position / same rough time of day, inside that 24–48 hour window, is the target — not "whenever there's a free hour" spread across a week.

Community-sourced notes (cross-referenced against the official guidance above)

Consistent with ElevenLabs' own docs: several independent write-ups from people who've actually built a PVC confirm the same core points — same-location recording matters more than gear quality, mixing recordings from different rooms or mic chains is the most commonly cited mistake, and going much past roughly an hour of source audio shows diminishing returns relative to the 1–3 hour official recommendation. Treat "diminishing returns past ~60 minutes" as a community observation, not an official ElevenLabs figure — it isn't contradicted by the docs, just not stated by them either.

eleven_v3 model-tier lever — separate from this recording project

Bo's own build spec (orchestrator/voice/PRD.md, section B2) already documents two separate levers for improving the current clone's quality: (1) the free lever, expanding the training sample with more/varied audio — that's what this recording session is — recommended FIRST; and (2) a model-tier lever, switching the TTS model from eleven_turbo_v2_5 to eleven_v3, which the same spec explicitly puts on HOLD pending a live-latency test on the demo line, since eleven_v3's call latency is unconfirmed for a real-time phone pipeline. Recording this script does not require or depend on that model-tier decision; it's the independent, no-downside lever the PRD itself recommends running first.

Open Questions — Stated Plainly, Not Guessed

Upgrade an existing clone, or start a new one? UNVERIFIED.

Whether ElevenLabs supports feeding additional training audio into an already-existing Professional Voice Clone (keeping the same voice_id Bo's pipeline already points at) versus requiring a brand-new clone with a new voice_id was not confirmed in any official documentation or community source checked for this page. The honest answer is: check the ElevenLabs dashboard directly against the specific voice already in use before recording, rather than assuming either path. If it does require a new voice_id, that's a one-line config change in orchestrator/voice/pipeline.py (ELEVENLABS_VOICE_ID / DEFAULT_VOICE_ID), not a rebuild.

Training-time estimate has a real conflict in the sources

Two independently-fetched official ElevenLabs documentation pages both state training/fine-tuning typically takes 3–6 hours, occasionally up to 24. One separate third-party 2026 tutorial blog claimed “3–4 weeks.” That number is not corroborated anywhere else checked and reads as either an error in that specific source or a description of something else (e.g. a manual Studio-Quality review track). This page treats the two official-doc figures as the reliable ones and flags the outlier rather than silently picking one.
