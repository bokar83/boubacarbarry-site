Root cause

Two separate failures are stacked on top of each other, and both point at the same gap: every block point in this pipeline except one is silent.

  • No forcing function moves a row from "written and scored" to "Queued." Approving a post and scheduling it are two different actions on the board, and only a human or an agent remembering to flip the Status field connects them. On July 9 this exact mistake was made and corrected once for the workshop rows; this audit shows it is not a one-off, it is the default failure mode - 18 more posts hit it going back to May 26.
  • The score gate has no alerting on the block path. auto_publisher's CTQ gate is doing its job (block underscored content, block unparseable scores), but it only writes a log line. The publish-failure path writes to the same log AND pings Telegram. The block path never got the same treatment, so a genuinely blocked post looks identical to a silently-stuck one from where you sit - you never hear about either.

Account-ID mapping (the fourth hypothesis in scope) is not the cause: LinkedIn and X both have valid Blotato account IDs configured, confirmed in the live .env and in the fact that 150+ rows have successfully published this way already.

The one structural fix

Recommendation: give the block path the same Telegram alert the failure path already has. Concretely, extend the existing auto_publisher heartbeat (or add one daily tick) to message you once a day with two lists, not zero:

  • Any row with a Scheduled Date in the past and Status still Ready / Draft / In Review / Idea - the "someone forgot to flip it to Queued" list.
  • Any Queued row that has failed the CTQ or Platform check for more than 24 hours - the "genuinely stuck, needs a human decision" list.

That turns a log line nobody reads into a message you actually see, the same way a failed publish already does. As a smaller companion fix: the score-text parser should also accept the pipe-delimited "Voice NN | CTQ NN" format that a chunk of the battery output actually uses today, so bucket 2's 13 posts stop being invisible to the gate. Both are small, contained changes - no redesign of the publish pipeline.

Verified code conditions (for the record)

Read directly from orchestrator/auto_publisher.py on the server. A row only auto-fires when every one of these is true:

1. Status == "Queued"                       (_fetch_due_queued, exact string match)
2. Scheduled Date <= today                   (date part only, time-of-day is ignored)
3. Platform resolves to a Blotato account id (_account_id_for_platform; LinkedIn, X,
                                               Facebook, Instagram, TikTok, YouTube,
                                               Pinterest, Bluesky, Threads only)
4. Today's slot time has arrived             (per-platform daily slots, default
                                               LinkedIn 07:00/11:00/12:00, X 07:00/11:00/14:00 MT;
                                               past-due dates skip this check)
5. CTQ score >= threshold                     (Total Score field, or Scores text parsed
                                               with regex \d+(\.\d+)?\s*/\s*(100|10);
                                               88 for most content, 90 for Content Type=Evergreen)
6. Not a Sunday in America/Denver             (Sabbath gate, whole tick no-ops)

On success: Status -> "Published", Posted Date set, platform-specific Posted URL written.
On failure: Status -> "PublishFailed", Source Note gets the error, Telegram alert sent.
On CTQ/platform block: a WARNING log line only. No board write, no alert.
