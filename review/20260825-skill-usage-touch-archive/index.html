Evidence-based recommendation · 2026-08-24

TL;DR

The SYS-685 skill-run ledger (which would give real invocation data) is built but not live — 4 test rows, no capture hook wired into main. Every "usage" number in this report is a labeled proxy (commit mentions, memory mentions, SKILL.md edit recency), not ground truth.

Boubacar's own claim is confirmed: checkpoint, tab-shutdown, and council/sankofa are real, heaviest-used skills by every proxy available.

Start the router-split with tab-shutdown and agentshq-absorb — the only two skills that are both genuinely thick AND provably hot across all three signals. checkpoint is next in line on usage-intensity even though it's mid-pack in size.

seo-strategy is the single biggest context-cost item in the repo (3,502 lines) but usage-cold in this pass — worth restructuring for size reasons alone, not on a "hot skill" justification.

A claimed "thick skill router split" PROCEED verdict was not found anywhere — not on main, not on any branch. 14 skills are real archive candidates on thin-size + zero-signal grounds. Zero files were edited, archived, or restructured as part of this analysis — every decision below is Boubacar's, per skill.

Method / evidence sources actually used (in the order tried)
  1. SYS-685 skill-run ledger — checked live, found NOT usable. The migration (065) and the PostToolUse capture hook exist only on unmerged branch origin/feat/sys-685-skill-run-ledger (commits 4b3007b3e, 9d98dab85 — both tagged [WIP], last commit 2026-08-22). git merge-base --is-ancestor confirms neither is an ancestor of origin/main. However the Postgres tables (skill_runs, skill_run_ledger_meta) DO exist live on the VPS (docker exec orc-postgres psql) — someone ran the migration by hand or during a branch test. Queried directly: 4 rows total, all dated 2026-08-23, all with lane='wt-sys685-ledger' (skills: checkpoint x2, karpathy, council). That is a one-time smoke test from building the ledger itself, not real usage capture — the capture hook is not wired into main's live .claude/settings.json or scripts/claude-hooks/ on the VPS (grepped, zero hits). Verdict: the ledger is not live and provides zero real usage data today.
  2. Proxy 1 — commit-message mentions on origin/main (git log origin/main --oneline -i --grep=<skill>), per skill.
  3. Proxy 2 — mentions across memory files (grep -rli <skill> over the real memory dir, not the stale mirrors).
  4. Proxy 3 (cleanest signal) — actual edits to each skill's own SKILL.md in the last 45 days on origin/main (git log --since --name-only -- 'skills/*/SKILL.md'). This is real maintenance/build activity, not a word match, so it's the least noisy of the three.
  5. Live-branch check — git branch -r scanned for any in-flight branch actively touching a given skill right now (separate from the misleading "checkpoint" hits, which turned out to be session-checkpoint docs branches, not edits to the checkpoint skill).
  6. The claimed absorb verdict itself — checked docs/reviews/absorb-log.md and docs/reviews/absorb-followups.md on origin/main, plus git log --all --since=2026-08-24, for any "thick skill router split" PROCEED entry. Not found anywhere — not on main, not on any branch. The line-count data (55 skills at 150+ lines, the top-10 list) is independently reproducible and was reproduced directly (see full list below), but the PROCEED verdict and its logging to those two files is unverified and should be treated as not landed until whoever ran it points to the actual commit.

Honest caveat on proxies 2/3: single common-English-word skill names (memory, active, brand, design, studio, library, forge, outreach, coordination, lead-gen) produce inflated commit/memory-mention counts from unrelated text, not real invocation. Those counts were not treated as reliable and were excluded from the buckets below unless corroborated by the 45-day SKILL.md-edit signal, which is substring-exact on the file path and not subject to the same noise.

UNKNOWN bucket — no real usage evidence, labeled rather than guessed

The proxies used here (git commit messages, memory file mentions, SKILL.md edit recency) measure how often a skill got worked on, not how often it got invoked by Boubacar or an agent in a live session — Claude Code does not log skill invocations anywhere durable today (that's exactly the gap SYS-685 was trying to close, and it isn't live). So for any skill that is genuinely invoked often but rarely needs editing and rarely gets name-dropped in a commit message or memory file (a "quietly reliable, never mentioned" skill), this evidence pass would wrongly under-count it. There is no way to distinguish "actually dead" from "actually fine, just stable" for skills sitting in the low-but-nonzero range (roughly the 3-10 mention band):

hyperframes-cli, youtube-10k-lens, 3d-website-building, website-to-hyperframes, vercel-cli-with-tokens, react-best-practices, pm-status, mermaid_diagrammer, studio-ugc-pipeline, studio-faceless-channel, baobab-ke, web-design-guidelines, remotion-best-practices, pallet-listing-copy, 3d-animation-creator.

Label these UNKNOWN, not archive-safe and not touch-first.
