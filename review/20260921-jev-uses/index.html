Jev: every use, every no, and the rule

DOC V2, research-02, 2026-09-21. Replaces V1 (kept collapsed at the bottom). Updated in place at this same URL.

TL;DR

  • Jev sorts and scores. A person decides anything that matters.
  • 42 uses listed, one line each, tap to open. 20 hard NO rules. One governance rule with GREEN / YELLOW / RED tiers.
  • Best new evidence: one hard question scored 62.6%, the same task split into five yes/no signals scored 95.0% (independent test). Graded by Jev at $160 per million answers it agreed with the top model 91.5% of the time (independent, 6,003 checks). Real speed and cost gains measured by others were ~5x to 25x and 8.6x, not the vendor's 200x and 444x.
  • Real failures: no way to say "I do not know" unless you add it, no explanation returned, confidence is unreliable off its home turf (0.74 stated at 44.7% real accuracy), high confidence that an action is right does not mean it worked.
  • Rule in one paragraph: Jev only orders queues, tags and advises. It never sends, pays, publishes, deletes, hires, fires or approves, and is never the only check on a damage-list action. Only public or invented text goes to it; anything private needs Boubacar's go-ahead for that dataset. Before it changes what happens it must beat our own labelled rows in a shadow run, have a named owner and a written confidence threshold; below that line, or on "unsure", a person decides. Every call is logged and capped, and the route is re-checked every 30 days (next 2026-10-21).
  • Deploy: Hostinger lags 10 to 15 minutes after a push.

The governance rule (full text in the repo: docs/governance/jev-governance-2026-09-21.md)

Adds guardrails only. It does not weaken or carve an exception into any existing hard rule, the damage list, the copy battery, the code model floor, or the install gate.

GREEN, use freely. Public or invented text. Low stakes and reversible. Orders, tags or advises only. Within cost caps, logged. Public text can hold hidden instructions, so GREEN never triggers an action.
YELLOW, proof first. Anything that changes what happens (routes, skips, holds), any non-public data, any client. Before it acts: a named owner, a shadow run on OUR labelled rows (200 minimum, 20 per calibration bucket, 90% agreement where not trivially reversible, zero misses on the must-catch class), a logged confidence threshold with the queue a person sees, and your dated go-ahead. Private data also needs your per-use go-ahead.
RED, never. Decisions about people. Acting on Jev's word alone. Sole check on a damage-list action. Writing, reasoning, maths, dates. Replacing a working rule. Security gating on inbound text. Installing into hooks, the Gate or daemons without Karpathy and Council. Promising Jev to a buyer. Quoting vendor numbers as evidence.
Privacy
  • Everything sent leaves the machine: OpenRouter, then TypeSafe. TypeSafe commits not to train on it; zero retention is enterprise-on-request only; OpenRouter retention is UNKNOWN.
  • Public or invented: free. Anything else: you say yes, per dataset, per session. No yes means RED.
  • No health, finance or immigration data at all until retention is confirmed in writing.
Confidence and escalation
  • Below the logged threshold a person decides. Every question has an explicit unsure option.
  • Unsure or an outage waits in a named queue. It never falls through to a default action.
  • Vendor floors 0.6 and 0.85 are illustrative, not ours.
Logging, caps, re-verification
  • Log every call: use id, state hash, answers, confidences, threshold, outcome, cost. Never a key, never raw private text.
  • Starting caps: $2 a day, $20 a month, all lanes. The client code does not enforce this yet, so it is discipline until a gated install adds it.
  • Every 30 days and before any new YELLOW use: price, limits, route, model id, data terms, failure page. Next due 2026-10-21.
Who can change it
  • Only you can loosen it. Agents can add guardrails. Promotion to live needs your dated go-ahead.
Gate results: Karpathy and Council
  • Karpathy: SHIP with changes. Invented thresholds now labelled starting values; calibration buckets need 20 rows so the bar is checkable; escalated items wait in a named queue instead of defaulting; enforcement stated honestly as written, not mechanical.
  • Council: Contrarian pushed for a real check plus the bucket minimum. First Principles added "do not use it just to save pennies". Outsider forced the plain-words box. Executor forced the seeded register and the fixed re-check date. Expansionist: the register plus shadow bar is a sellable client offer.

How NOT to use it (20 rules)

N1Writing, explaining, reasoning, counting, maths, dates
  • Why: TypeSafe's own jaggedness page: literal reading, counting error grows with size, dates read as text
  • Instead: Do the maths and dates in code; Jev only answers bounded questions.
N2A wrong answer that is costly or hard to undo: hiring, firing, discipline, legal, medical, financial, security
  • Why: Simon Willison: a floating-point number can hide bias; vendor and reviews say never irreversible execution alone
  • Instead: A person decides. Jev may only order a queue.
N3Sending, publishing, paying, deleting or granting access on Jev's word
  • Why: Tier C damage list in our rules; Reticle: action confidence is not action success
  • Instead: Jev decides what a person looks at first, never what happens.
N4Sending private, PII, client, family, health or finance data off the machine without the owner's per-use go-ahead
  • Why: OpenRouter and TypeSafe both see it; OpenRouter retention UNKNOWN; TypeSafe zero-retention is enterprise-on-request only; one dossier notes US-only hosting
  • Instead: Public or invented text is free. Everything else asks first, every time.
N5Treating vendor benchmark numbers as truth
  • Why: Vendor score is agreement with two LLMs, not correctness, on workflows its own team wrote; Every measured ~25x not 200x; Near Here ~5x/8.6x not 444x
  • Instead: Only our own labelled sample counts.
N6Replacing a working deterministic rule
  • Why: Regex and ban-list checks are exact and free; Jev is a probability
  • Instead: Jev goes beside the rule as a second signal, never instead.
N7Being the only check on a damage-list action
  • Why: Reticle 'never': it answers what to do next, not whether it worked
  • Instead: Second independent signal plus a human, always.
N8Acting on low confidence
  • Why: Vendor floor 0.6, 0.85 for high stakes; independent ECE 0.107; 0.74 stated confidence at 44.7% real accuracy; confidence ranked errors no better than baseline on CLINC150
  • Instead: Under the logged threshold, a person decides.
N9Unbounded volume or cost loops
  • Why: Doom ~$7/hour; a Smash Bros run used 22M+ tokens; trader loop every 300ms
  • Instead: Per-run, per-day and per-month caps plus a kill switch.
N10No logging
  • Why: No rationale is returned; a wrong and a right answer look identical
  • Instead: Log question text, option text, state hash, answer, confidence, outcome.
N11Forcing a choice with no way out
  • Why: Reticle: Jev cannot abstain unless you add an 'unsure' option
  • Instead: Every Choice includes an explicit unsure/needs-review option.
N12Treating the alpha route as stable
  • Why: Route is alpha, absent from OpenRouter's model list, docs and API disagree in places (403 vs 401, 400 vs 422)
  • Instead: Re-verify every 30 days and before any new YELLOW use; fail open to a person.
N13Feeding hostile text as state and trusting the answer
  • Why: TypeSafe: injected instructions can steer answers; classifying inbound mail is exactly that exposure
  • Instead: Never let Jev gate security, access or an inbound-triggered action.
N14Long or padded input
  • Why: 32K data cliff: too much input fails the call; accuracy drops with irrelevant detail
  • Instead: Filter in code first, batches of about 10.
N15One big hard question
  • Why: Single 'is this phishing' 62.6%; five atomic signals 95.0%
  • Instead: Decompose into atomic yes/no signals.
N16Ranking or scoring people
  • Why: Willison Cupertino test showed a hidden geographic bias
  • Instead: No person-scoring. Business fit only, on public data.
N17Relying on option order or field names
  • Why: Reversing order shifts probabilities; Reticle: field names carry zero instruction
  • Instead: Shuffle/pair-test order; put the instruction in the question text.
N18Promising Jev, or 'zero hallucination', to a buyer
  • Why: Zero hallucination means valid format only; a wrong valid answer still happens (CEO conceded on HN)
  • Instead: Describe the outcome, never the tool (our no-Vapi rule already says this).
N20Using hosted Jev as the privacy check ('is this private?')
  • Why: The question itself already sent the content to OpenRouter and TypeSafe; a builder had to swap to a local open clone (88 ms) for this reason (absorb youtu.be/ZR7anrL50xs, INDEPENDENT reasoning)
  • Instead: Privacy screening is rules-first (regex/allowlist in code) BEFORE any hosted call; ambiguous goes to a person or a local model, never to hosted Jev.
N19Putting Jev into a hook, Gate, daemon or harness path without the install gate
  • Why: Existing rule: Karpathy + Council before anything installed
  • Instead: Karpathy + Council first, recorded.

Patterns to reuse

  • One call, several independent questions. Same state, parallel questions (lane, difficulty ladder, privacy, needs-web) for about the cost of one. Vendor mechanism; the demo is a one-shot anecdote.
  • Privacy as a hard override. A privacy flag forces the safe route and low confidence fails SAFE (local or a person). The flag is computed by rules in code, not by hosted Jev.
  • Jev decides, LLM writes. Jev picks route/priority/yes-no; a writing model drafts. Never the reverse.
  • Cheap-first cascade. Jev screens everything; only the unsure or the flagged go to a bigger model or a person.
  • Confidence-threshold escalation. Below the logged threshold a person decides (vendor floor 0.6, 0.85 for high stakes, ours calibrated on our data).
  • Decompose-and-weight. Five atomic yes/no signals plus a small weighting model beat one hard question (62.6 to 95.0).
  • Shadow-mode replay. Run beside the incumbent on 200 to 2,000 labelled rows before it acts on anything.
  • Grade with Jev, re-grade disagreements. Jev grades all, an LLM re-grades only the rows where they split.
  • BM25 then Jev rerank. A free retrieval step fetches 100, Jev only orders them.
  • Always give it an unsure option. Jev cannot abstain unless you add the option.
  • Candidate prefilter. Cut the field in code (embedding, regex, date math) before Jev sees it.
  • Second signal, never sole signal. Jev sits beside a rule or a person, never alone on a damage-list action.

Best ways to use JEV today

Research-02, 2026-09-21. Spikes only, no builds Mon-Fri.

TL;DR

  • Jev IS on OpenRouter (typesafe/jev-1.13, $0.042 per million input, output free, 32K). The OpenRouter-only blocker is gone.
  • But it is NOT in OpenRouter's model list (443 checked today). It uses a separate alpha Decisions endpoint that may move.
  • It decides, it does not write. Best for high-volume classify, score, yes/no with a confidence gate.
  • Our own decision points already run on cheap models, so internal savings are pennies. The real prize is a cheap client diagnostic.
  • Accuracy is vendor-claimed: 67.8% vs 73-74% for the best models. No independent large test found.
  • Recommendation: run the 200-row bakeoff first (1 hour), then the client-data diagnostic on the same rows.

Top 3 (ranked)
1. Client-data baseline diagnostic. The only idea that feeds Year One (fractional HR/AI client first). Score a client's own 1,000 emails or tickets for cents, hand back a one-pager. First test: our own inbox export.
2. 200-row bakeoff on our reply rows. The un-park trigger already on file. One hour, settles the accuracy question with our data. Do this first.
3. HR helpdesk triage with sensitive escalation. Fits the HR positioning. Safe only if harassment, leave and medical always go to a human. Runner-up: quote-form routing, the one direct $500-1k product (price unvalidated).
