AI Phone Calls
Research & Implementation Plan

How to build an outbound AI calling system inside agentsHQ that sounds human, schedules appointments, and can eventually pick up Boubacar's calls when he's busy.

Date: 2026-06-28 Verdict: Build Pipecat. Validate on ElevenLabs ConvAI today. First call: 1-4 hours from now
TL;DR

Build: Pipecat (open source, Python/Docker) + Twilio Media Streams + Deepgram STT + OpenRouter → Claude + ElevenLabs turbo. That's the durable self-hosted stack that fits agentsHQ perfectly.

But don't build it first. Validate today on ElevenLabs Conversational AI (1-4 hours to first call) to learn what end-of-turn failures actually sound like before committing dev weeks.

Legal hard stop: cold AI calls to non-consented cell numbers = TCPA strict liability, $500-$1,500 per call, no cap. Scope Phase 1 to warm/consented confirmation calls only. One list of 1,000 cold cells = up to $1.5M exposure.

01 The Recommended Stack▼

Every layer chosen for stack-fit and hard rules (all LLM via OpenRouter, ElevenLabs already contracted, Python/Docker native).

Framework
Pipecat (pipecat-ai)
Open source BSD-2, 13k GitHub stars. Python pipeline: STT→LLM→TTS. Native Twilio, ElevenLabs, Deepgram, AND OpenRouter support. Runs in Docker Compose alongside orc-crewai.
Telephony
Twilio Programmable Voice
PSTN unavoidable — you can't run your own phone network. Twilio Media Streams = WebSocket audio to your VPS. $0.013/min outbound. Migrate to SignalWire (~55% cheaper) at scale.
Speech-to-Text
Deepgram Nova-2/Nova-3
~150ms first-word latency. Native `utterance_end` event (critical for natural turn detection). Streaming, not batch.
LLM — ALREADY WIRED
OpenRouter → Claude Sonnet 4.6
Hard rule: ALL LLM via OpenRouter. `OpenRouterLLMService` is a native Pipecat class. No change to existing routing.
TTS — ALREADY CONTRACTED
ElevenLabs eleven_turbo_v2_5
Already in the stack. MUST use turbo model only — standard models add 800ms+ latency and blow the budget. First-byte: 75-150ms.
VAD (Voice Activity Detection)
Silero VAD (local PyTorch)
Under 5ms latency, no API cost, handles barge-in (human interrupts AI mid-sentence). Open source, runs on VPS CPU.
Storage — EXISTING
Postgres (orc-postgres)
Call sessions, per-turn timing telemetry, transcripts, consent flags. No new infra.
Alerts — EXISTING
Telegram notifier
Call started/booked/failed. Same notifier.send_message() pattern as everywhere else.
Drop OpenAI Realtime API

Every council member and Karpathy flagged this: OpenAI Realtime does its own TTS (speech-to-speech model), so bolting ElevenLabs on top is architecturally incoherent. Also violates the OpenRouter-only rule. Drop it entirely — the cascade above (streaming text LLM via OpenRouter + separate ElevenLabs TTS) is the right design.

Why per-turn telemetry is mandatory, not polish

A phone call is non-reproducible. When "it talked over the caller on minute 2" happens, you have one chance to get that data. Per-turn timing (VAD fire timestamp, STT latency, LLM TTFT, TTS first-byte, barge-in events) is the only way to debug the specific failure. Log it or debug blind forever.

Crossover ≈ 5,000 calls/month. Below that, managed (D) is cheaper once you price the build honestly. Above that, Pipecat's 3-5x margin pays back the $6-12k build in 1.5-2.5 months.

The number that actually matters: cost per BOOKED appointment

Cold connect rates are 1-5%. 60-80% of dials hit voicemail (all billed). 10,000 dials → 200-500 connects → 20-50 bookings → $30-75 per booked appointment even at self-hosted rates. Price and sell on "appointments booked," never "AI minutes." Warm confirmation calls have far higher connect rates — another reason warm is the real business.

04 Phase 1: First Working Call Today▼

Goal: hear a real AI call on your cell today. Disposable. Zero reusable code. Only output is a yes/no on whether the appointment flow works.

  1. Hour 0-1 — Create ElevenLabs ConvAI agent. ElevenLabs dashboard → Agents → Create agent. Voice = existing ElevenLabs voice. TTS model = eleven_turbo_v2_5. Set custom LLM endpoint = https://openrouter.ai/api/v1, model = anthropic/claude-sonnet-4.6. Pull OPENROUTER_API_KEY from .env. This satisfies the LLM hard rule from minute one.
  2. System prompt. Role: appointment scheduling assistant. MUST open with the legal disclosure (see Compliance section). Goal: confirm one of 3 offered time slots + capture email (confirm-by-spelling).
  3. Hour 1-3 — Wire telephony. Connect a Twilio number via ElevenLabs' native Twilio integration (no TwiML needed). If no number exists, buy one (~$1/mo, 15 min) — calling your OWN cell needs no A2P trust registration.
  4. Trigger an outbound call to your cell. What you hear Day 1: actual first-word latency (~1-1.5s), real barge-in behavior, whether slot+email capture works or breaks.
  5. Hour 3-4 — Bridge results to Postgres. Configure ElevenLabs post-call webhook → tiny FastAPI endpoint writing outcome + transcript to voice_calls table.
Why throwaway first, build second

The biggest wastes in voice AI are building the whole Pipecat stack, deploying it, and then discovering that end-of-turn detection has a 2-second dead-air problem that requires 2 weeks of tuning. Phase 1 is insurance: it either validates the appointment flow works (proceed to Phase 2) or reveals the conversation design is broken (fix before the big build). If Phase 1 fails, you just saved $6-12k and several weeks.

06 Phase 3: Inbound Autoresponder▼

Same voice-server, different entry point. When Boubacar's busy, the AI picks up.

  1. Buy/port a Twilio inbound number, OR configure forward-on-no-answer from your cell to it.
  2. Twilio inbound webhook → same /twiml → same <Connect><Stream> → same Pipecat pipeline.
  3. Swap system prompt to receptionist: "Boubacar is unavailable right now. I'm his AI assistant. I can take a message or book a time on his calendar."
  4. Function calls: take_message(caller, summary) → Telegram to Boubacar; book_callback(caller, slot) → calendar.
Inbound is legally simpler

The caller initiated contact, so TCPA outbound-consent rules don't apply. Still disclose AI at the start (Utah AI Policy Act; also the trust move that prevents "wait, am I talking to a robot?" trust collapse). Inbound call handling is also the highest-value dogfood use case — it's immediately useful to Boubacar personally.

Concurrency limit: ~5-15 calls on 8GB VPS

Inbound + outbound share one VPS event loop. Call 16 doesn't error — it just gets slow (silent degradation). Add a concurrency watermark Telegram alert before going live.

07 Compliance: Exactly What to Say▼

TCPA Hard Stop — Read This First

Cold AI calls to non-consented cell numbers = TCPA strict liability = $500-$1,500 per call, no cap, no intent defense. One list of 1,000 cold cells = up to $1.5M exposure. The trigger_outbound_call() function must hard-gate on a consent flag and refuse to dial without it. This is not optional.

Exact Opening Disclosure (every call, outbound and inbound)
"Hi, this is an AI assistant calling on behalf of Boubacar Barry. This call may be recorded, and you can ask me to stop at any time. I'm reaching out to confirm a time for [purpose]."

Why it works: satisfies TCPA caller-ID disclosure, satisfies Utah AI Policy Act (disclose AI at start of any AI interaction in sales/solicitation context), prevents the "wait, is this a robot?" trust collapse, and triggers the opt-out you're legally required to honor immediately.

Live In-Pipeline Opt-Out Detector

If caller says "stop calling," "remove me," "take me off your list" → immediate hangup + synchronous DNC write. This runs IN the call, not in post-call analysis. Async DNC write is a TCPA violation — the opt-out must be honored before the call ends.

Must Log Per Call (Retain 5+ Years)

  • Timestamp + timezone of the call
  • Number called
  • Consent reference (how/when consent was obtained)
  • DNC scrub date (scrub both federal + Utah state DNC within 31 days; daily is best practice)
  • Opt-out status
  • Transcript/recording reference
  • Outcome (booked / declined / opted-out / no-answer)

Utah-Specific (before any real outbound telemarketing)

Register with Utah Division of Consumer Protection ($500/yr) + $50K surety bond. Call hours: 8 AM-9 PM recipient-local. Confirmation calls stay informational — the moment you add an upsell, it becomes marketing and requires prior express written consent.

08 What Council + Karpathy Found▼

Council Verdicts (5 Angles)

Technical Feasibility
agentsHQ can build this, but the hard part is never the happy-path demo — it's barge-in tuning, end-of-turn detection, and 24/7 WebSocket reliability. Start on managed to learn what "good" sounds like, then graduate to Pipecat. Buildability: Pipecat 7/10, ElevenLabs ConvAI 9/10. Maintainability: Pipecat 6/10 (you own the plumbing), ConvAI 8/10.
Cost & ROI
Self-hosted (Pipecat) is wrong FIRST build — dev cost only amortizes above ~5,000 calls/mo. Validate with managed first, port to self-hosted when volume or resale justifies it. A $0.15/call variable cost means $30-75/booked appointment at realistic dial-connect rates — price on appointments, never on minutes.
Voice Quality & Human Realism
ElevenLabs wins TTS outright. But TTS timbre is only ~30% of perceived "humanness." The other 70% is end-of-turn detection and barge-in atomicity — engineer the turn-taking layer, not the voice. A 500ms dead-air after the human stops talking sounds more robotic than any voice model choice.
Speed to First Call
ElevenLabs ConvAI: 1-4 hours. Vapi: 1-3 hours. Pipecat from scratch: 8-16 real hours (not "2-4 days" — that's the demo, not production). Dogfood today on ElevenLabs ConvAI. Build Pipecat in parallel.
agentsHQ Integration
Pipecat is the only approach that puts call flow inside the Python orchestrator, logs natively to Postgres, and can't be TOS-banned mid-campaign. Architecture: decoupled voice-server container — phone calls are real-time (WebSocket), orchestrator is async (queue). They share only Postgres + Twilio webhooks. Never write a synchronous "wait for call to end" function — the LLM context would time out on a 5-min call.

Karpathy 10-Principle Audit — Top Findings

P1 — First Principles: What is the actual goal?
Not "make AI calls." The goal is: save Boubacar 2-3 hours/week of appointment-scheduling time. A warm confirmation call that books 80% of slots is worth 10x a cold calling campaign that books 2% at legal risk.
P2 — Simplicity: The simplest thing that works
ElevenLabs ConvAI + Twilio + a webhook = first working call in hours. Pipecat is the right eventual home, not the right starting point. The two-phase approach respects simplicity.
P7 — Debugging: How do you debug a bad call?
A phone call is non-reproducible. Per-turn telemetry (VAD fire → STT latency → LLM TTFT → TTS first-byte → barge-in timestamps) in Postgres is the ONLY way to diagnose "it talked over the caller at minute 2." This is mandatory logging, not optional polish.
P10 — Failure Modes: Name all of them
TCPA exposure (company-ending). Phantom bookings (trust-destroying). TTS mangling emails/phone numbers (costly). Robot-sounding dead-air (adoption-killing). Silent VPS concurrency overload (no error, just slow calls). Voicemail answers getting billed and receiving TCPA-violating prerecorded messages.
Karpathy Overall Verdict
Build A (Pipecat cascade), validate on D (ElevenLabs ConvAI) as throwaway. The legal risk is the #1 project-killer if not addressed in code. The #1 success factor is owning the turn-taking layer — not managed by anyone else.

09 Risks & Kill Conditions▼

Risk 1 — THE Killer: TCPA / Utah Legal Exposure

Cold AI calls to non-consented cells = strict liability. No intent defense. $500-$1,500/call, no cap. One list of 1,000 cold cells = up to $1.5M exposure.

Prevention: consent-gate in trigger_outbound_call() code (hard refuse without consent_ref), warm-only scope for Phase 1, AI disclosure opener, live opt-out detector in-pipeline, Utah DCP registration + $50K bond before any real campaign. Kill condition: if no warm consented list exists, the cold version should not ship.
Risk 2 — Make-or-Break: It Sounds Like a 2019 IVR

Human realism is 70% turn-taking / barge-in, not voice quality. Silero VAD detects sound stopped — not that the human is DONE. Dead-air and talking-over failures are the #1 adoption killer.

Prevention: own the turn-taking layer (Pipecat, not managed), per-turn telemetry, Deepgram utterance_end + 200ms fallback, Hamming AI for simulated regression testing (you can't legally hand-dial 200 test calls). Kill condition: if still talking over people after tuning, don't scale.
Risk 3 — Silent Trust Destroyers: Phantom Bookings + Readback Errors

AI says "you're booked" but calendar write failed → no-show → client rage. TTS mangles spoken emails (B-O-U-B-A-C-A-R isn't obvious). Voicemail answers don't know they're talking to nobody.

Prevention: verify-after-write mandatory (re-fetch event, assert exists, THEN confirm), confirm-by-spelling for all captured emails/numbers, answering-machine detection (hang up early; don't leave a prerecorded TCPA-violating voicemail). Kill condition: booking accuracy below ~95% in testing = fix before any client touches it.
