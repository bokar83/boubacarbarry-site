D. Migration-logic fixes (for any future reorg, not just this dataset)
  1. Folder-coherence gate before any move: classify every source folder COHERENT vs CATCH-ALL first (checklist in Section F); item-level routing only inside declared catch-alls, justification logged. (Kills RC1.)
  2. Topic magnets over path mirrors: one canonical destination per topic; matching FOLDERS route there regardless of the path they came from. (Kills RC2.)
  3. Coverage ledger with hard fail: every source top-level folder gets exactly one recorded disposition; an unmapped folder is a blocker, not a silence. (Kills RC3, F4.)
  4. Verify-after-copy per unit: recursive file count + md5-set equality; Google-native files reconciled by name+parent and quarantined; any mismatch halts the run. (Kills RC4, F5.)
  5. Dedup strictly after consolidation, inside the destination, md5 only, one quarantine (90). Never pre-fragment sources into dup-buckets. (Kills RC5.)
  6. Media units are atomic. (Kills RC6.)
  7. Sensitive folders are opaque IDs: move whole by ID, zero content reads, zero names in outputs.
  8. Two-phase landing: land whole at the magnet, organize inside the destination afterward. Never reorganize mid-flight.
  9. Dev-junk exclusion list: node_modules, .git, dist, build, __pycache__ never migrate and never count in verification.
  10. Manifests are inputs: the prior run's own manifests (00 _SYSTEM/_reports: migration-manifest.csv, manifest-summary.json; _REVIEW folders) seed the coverage ledger instead of recomputing blind.
  11. Operational: bulk enumeration = folders first (cheap), files only per-scope with streaming and a memory cap, never unbounded inside the production container. Two full-drive file fetches tripped the 1.5GB container into restarts during this audit; the safe pattern is documented in the Method section.
  12. Copy vs move discipline: within the working tree, MOVE (reparent by ID). COPY only from a declared frozen reference. Declare which tree is canonical before the first operation; state the endgame for the reference tree (here: Boubacar manually decides the fate of _ORIGINAL_TREE after all verifications pass, agents never delete).

Why the rules are shaped this way

  • Precedence = retrieval order. The tree mirrors how content is asked for: "everything about Guinea" (entity) beats "my tax stuff" (domain) beats work-vs-personal beats "old stuff" beats "some video." A placement that cannot be restated as one of these rules is by definition wrong and goes to the inbox instead.
  • Tax year = year covered, because the accountant and the IRS ask by tax year; filing by received-date scatters one year's return across two folders.
  • Move-whole bias is deliberate: the cost of wrongly moving a dump whole is one messy-but-findable folder; the cost of wrongly splitting a coherent folder is this entire incident.
  • Greppability: canon names + alias table + the depth cap mean a future AI can predict a path (10 Me & Mine / Finances & Taxes / Taxes / 2024 / ...) without listing the tree first.
