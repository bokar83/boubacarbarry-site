TL;DR: 32 languages are usable on Bo today with the current low-latency stack (English, French, Spanish, Portuguese, Mandarin Chinese, Arabic, Russian, and 25 more — full list below). A further 43 languages have real-time STT and SOME TTS voice, but only via ElevenLabs' higher-quality eleven_v3 model, whose live-call latency is not confirmed (no published low-latency figure, unlike Turbo/Flash). Of your 7 originally-named priority languages: French is fully supported. Fulani/Fula/Pulaar is half-supported (Bo could understand it live, but no provider has a voice that can speak it back). Haitian Creole, Mauritian Creole, Malinke/Maninka/Mandingo, Bambara, and Susu/Soso are not currently feasible with either provider — none appear in any real-time STT or TTS language list checked. Cantonese Chinese (which you asked about alongside Mandarin) has real-time STT but no TTS voice on either ElevenLabs model — Mandarin and Cantonese do NOT travel together the way you might expect.

2. The limitations, plainly

  • No hard cap on language count. Neither Deepgram's nor ElevenLabs' docs describe a limit on how many languages a single account or integration can use — language is a per-request parameter, not a fixed roster you provision. The real ceiling is which languages each MODEL supports, not how many you try to turn on.
  • Two different quality/latency tiers on the TTS side. ElevenLabs Turbo v2.5 / Flash v2.5 (32 languages, ~75ms latency, published) is the model this pipeline already uses for live calls. ElevenLabs eleven_v3 covers far more languages (70+, including Hausa, Swahili, Somali, Afrikaans and others) but is positioned for audiobooks/character dialogue, not real-time conversation, and has no published low-latency figure. It MAY still work on a phone call, but that is not confirmed — it would need a live latency test before being trusted on a real call.
  • Per-language setup is not zero-cost even for a "supported" language. Each newly-enabled language needs: (a) the correct Deepgram language code wired in, (b) a human listening test of Bo's current voice_id in that language — ElevenLabs' multilingual models can technically speak a language without necessarily sounding as natural as they do in English, this is not something a docs check can verify, and (c) a system-prompt check that Bo's tone/phrasing in that language doesn't read stiff or mistranslated — voice and tone patterns do not always carry over directly from the English-tuned prompt.
  • Claude's own conversational competence is a separate, real bottleneck for lower-resource languages, independent of whether STT/TTS technically list them. French, Spanish, Portuguese, Mandarin, Arabic, Russian are all well-resourced languages with strong LLM performance. Lower-resource languages in the "usable, latency unverified" tier below (e.g. Swahili, Hausa, Somali) likely have measurably weaker LLM production quality even where STT+TTS technically exist — this needs a real conversation test per language, not just a docs check, before being trusted live.
  • A call where transcription works but the reply is broken is worse than not offering the language. This is why Fulani is marked PARTIAL rather than supported, and why the 43-language "unverified latency" tier below is not being wired into the pipeline yet.
